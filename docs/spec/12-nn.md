# ニューラルネットワーク仕様

## 概要

盤面とコンテキスト情報（3ツモ）から配置確率と盤面価値を出力する Dual Head Network（CNN + FiLM Conditioning、Policy Head + Value Head）のモデル定義と入力エンコーディングを提供する。機械学習フレームワークには [Burn](https://burn.dev/) を使用する。

## クレート構成

```
crates/puyo-nn/
├── src/
│   ├── lib.rs              # モジュール公開
│   ├── encoding.rs         # 盤面 → テンソル変換
│   ├── model.rs            # CNN モデル定義
│   └── value_transform.rs  # MuZero Invertible Value Transform
└── Cargo.toml
```

## 盤面エンコーディング (`encoding`)

盤面を6チャンネルの浮動小数点テンソルに変換する。チャンネル0〜3は色one-hot形式、チャンネル4は占有マップ、チャンネル5は連結度マップ。

### 定数

| 名前 | 値 | 説明 |
|------|-----|------|
| `NUM_CHANNELS` | 6 | color one-hot 4ch + occupancy 1ch + adjacency 1ch |
| `TENSOR_SIZE` | 504 | `NUM_CHANNELS × ROWS × COLS` = 6 × 14 × 6 |
| `CONTEXT_TENSOR_SIZE` | 24 | ツモ one-hot 24（`PIECE_TENSOR_SIZE`） |

### テンソルレイアウト

```
[channel][row][col] = [6][14][6]
```

| チャンネル | 内容 | 値域 |
|-----------|------|------|
| 0 | Red (one-hot) | {0, 1} |
| 1 | Green (one-hot) | {0, 1} |
| 2 | Blue (one-hot) | {0, 1} |
| 3 | Yellow (one-hot) | {0, 1} |
| 4 | 占有マップ (occupancy) | {0, 1} |
| 5 | 連結度マップ (adjacency) | [0, 1] |

#### チャンネル0〜3（色one-hot）

各セル `(col, row)` の色に対応するチャンネルが 1.0、それ以外は 0.0。Empty セルは全チャンネル 0.0（4色の排他性から暗黙的に判定可能）。

#### チャンネル4（占有マップ）

ぷよが存在するセルは 1.0、Empty セルは 0.0。色に依存しない空間構造情報を提供する。

#### チャンネル5（連結度マップ）

各セルの上下左右4方向について同色の隣接ぷよ数をカウントし、4.0 で割って正規化。Empty セルは 0.0。連鎖の種となる同色グループの構造を表現する。

### インデックス計算

```
index = channel * ROWS * COLS + row * COLS + col
```

### API

```rust
pub fn board_to_tensor_data(board: &Board) -> [f32; TENSOR_SIZE]
pub fn pieces_to_tensor_data(current: &Piece, next: &Piece, next_next: &Piece) -> [f32; PIECE_TENSOR_SIZE]
pub fn context_to_tensor_data(current: &Piece, next: &Piece, next_next: &Piece) -> [f32; CONTEXT_TENSOR_SIZE]
```

### 盤面テンソル変換

`board_to_tensor_data` で得られた `[f32; 504]` の1次元配列は、NN に入力する際に4次元テンソルに reshape する。

```
[504] → reshape → [batch, 6, 14, 6]
                   │      │   │   └── COLS
                   │      │   └────── ROWS
                   │      └────────── NUM_CHANNELS
                   └───────────────── バッチサイズ
```

### ツモエンコーディング

`pieces_to_tensor_data()` は3ツモ（current, next, next_next）の色情報を24次元ベクトルに変換する。

```
3ツモ × 2色（axis, satellite） × 4色 one-hot = 24次元
```

各ツモの axis_color と satellite_color をそれぞれ4色の one-hot（Red, Green, Blue, Yellow）に変換し、順に連結する。

### コンテキストエンコーディング

`context_to_tensor_data()` はツモ情報を24次元ベクトルに変換する（`pieces_to_tensor_data()` と同等）。

```rust
pub fn context_to_tensor_data(current: &Piece, next: &Piece, next_next: &Piece) -> [f32; CONTEXT_TENSOR_SIZE]
```

API一覧:

```rust
pub fn board_to_tensor_data(board: &Board) -> [f32; TENSOR_SIZE]
pub fn pieces_to_tensor_data(current: &Piece, next: &Piece, next_next: &Piece) -> [f32; PIECE_TENSOR_SIZE]
pub fn context_to_tensor_data(current: &Piece, next: &Piece, next_next: &Piece) -> [f32; CONTEXT_TENSOR_SIZE]
```

## CNN Dual Head Network (`model`)

### アーキテクチャ: `PuyoNet`

盤面とコンテキスト情報（3ツモ）を入力として、24次元の配置 logits（Policy Head）と1次元の盤面価値（Value Head）を出力する Dual Head モデル。Residual接続（残差接続）と FiLM Conditioning を採用し、コンテキスト情報に基づいて特徴マップを条件付けする。

#### FiLM Conditioning

Feature-wise Linear Modulation（FiLM）により、コンテキスト情報を畳み込み特徴マップに注入する。

FiLM ジェネレータは 768 次元を出力し、6つの残差ブロックにそれぞれ独立した (gamma[64], beta[64]) を供給する（**per-block FiLM**）:

```
context(24) → Linear(24→128) → ReLU → Linear(128→768) → split → 6 × (gamma[64], beta[64])
```

各 `ResidualBlock` には専用の gamma/beta が渡され、コンテキスト情報をブロックごとに異なる方法で特徴マップに注入できる（以前は全ブロック共有の gamma[64]/beta[64] を使用）。

#### Residual FiLM 方式

FiLM の適用には **Residual FiLM** 方式を採用する:

```
y = x * (1 + gamma) + beta
```

gamma=0、beta=0 のとき恒等変換となり、FiLM の効果がない初期状態でも通常の残差ブロックと同等の挙動が保証される。以前の `y = x * gamma + beta` では gamma=0 のとき特徴マップが消滅してしまう問題があった。

#### `ResidualBlock`

GroupNorm と Residual FiLM Conditioning を内蔵する残差ブロック。

```
x → Conv(3×3) → GroupNorm → ReLU → Conv(3×3) → GroupNorm → Residual FiLM(gamma, beta) → (+skip) → ReLU → y
|                                                                                             ↑
└─────────────────────────────────────────────────────────────────────────────────────────────┘
```

- GroupNorm は `num_groups=1`（Layer Norm 相当）で各畳み込み後に適用される。バッチサイズに依存しない正規化により、小バッチや推論時の学習安定性が向上する
- Residual FiLM: `y = x * (1 + gamma) + beta`。gamma/beta は [batch, channels] → [batch, channels, 1, 1] にリシェイプしてブロードキャスト

#### 全体構成

| レイヤー | 種類 | 入力 | 出力 | カーネル | パディング | 備考 |
|---------|------|------|------|---------|-----------|------|
| film_gen | Linear×2 | 24 | 768 | - | - | FiLM ジェネレータ（隠れ層128→6ブロック分 gamma+beta） |
| stem | Conv2d | 6ch | 64ch | 3×3 | Same | 入力チャンネル射影 |
| relu | ReLU | - | - | - | - | |
| res_block ×6 | ResidualBlock | 64ch | 64ch | 3×3 | Same | GroupNorm + per-block Residual FiLM 条件付き残差接続 |
| head_conv | Conv2d | 64ch | 128ch | 1×1 | - | チャンネル拡張 |
| relu | ReLU | - | - | - | - | |
| pool | AdaptiveAvgPool2d | 128ch | 128ch | → 4×3 | - | |
| flatten | Reshape | 128×4×3 | 1536 | - | - | 共有特徴ベクトル |
| **Policy Head** | | | | | | |
| policy_linear1 | Linear | 1536 | 256 | - | - | |
| relu | ReLU | - | - | - | - | |
| policy_linear2 | Linear | 256 | 24 | - | - | 配置 logits |
| **Value Head** | | | | | | |
| value_linear1 | Linear | 1536 | 256 | - | - | |
| relu | ReLU | - | - | - | - | |
| value_linear2 | Linear | 256 | 1 | - | - | 盤面価値（活性化関数なし、生出力） |

#### 定数

| 名前 | 値 | 説明 |
|------|-----|------|
| `RESIDUAL_CHANNELS` | 64 | Residualブロック内のチャンネル数 |
| `NUM_RESIDUAL_BLOCKS` | 6 | Residualブロックの個数 |
| `HEAD_CHANNELS` | 128 | ヘッド部のチャンネル数 |
| `POOL_H` / `POOL_W` | 4 / 3 | AdaptiveAvgPool2d の出力サイズ |
| `HIDDEN_SIZE` | 256 | 全結合層の隠れ層サイズ |
| `NUM_ACTIONS` | 24 | Policy Head 出力次元（6列 × 4方向） |
| `CONTEXT_TENSOR_SIZE` | 24 | コンテキスト入力次元（ツモ one-hot 24） |
| `FILM_HIDDEN` | 128 | FiLM ジェネレータ隠れ層サイズ（旧: 64） |
| `FILM_OUTPUT` | 768 | FiLM ジェネレータ出力サイズ（`64 × 2 × 6`、全ブロック分のgamma+beta） |

### 入出力

- **盤面入力形状**: `[batch, 6, 14, 6]`（color one-hot + occupancy + adjacency エンコード済み盤面）
- **コンテキスト入力形状**: `[batch, 24]`（3ツモの色 one-hot 24）
- **出力形状**: `(Tensor<B,2>, Tensor<B,2>)` = `([batch, 24], [batch, 1])`（policy_logits, value）

### 初期化

```rust
let config = PuyoNetConfig::new();
let model = config.init::<B>(&device);
```

## Value Transform (`value_transform`)

MuZero の Invertible Value Transform を実装する。累積割引報酬（0〜数千）のスケールを圧縮し、MSE 損失を安定させる。

```
h(x) = sign(x) × (√(|x|+1) - 1) + ε×x     （ε = 0.001）
```

- **学習時**: value_target に `value_transform()` を適用してから MSE 損失を計算
- **推論時（MCTS）**: ネットワーク出力に `value_inverse_transform()` を適用して元スケールに復元

Value Head の出力自体は Linear（活性化関数なし）のまま。sigmoid/tanh を使わない理由は、飽和による勾配消失を避けるため。

### API

```rust
pub fn value_transform(x: f32) -> f32          // 順変換: 大きな値を圧縮
pub fn value_inverse_transform(y: f32) -> f32   // 逆変換: 元スケールに復元
```

## モデルの保存・読み込み

| 用途 | レコーダー | 形式 |
|------|-----------|------|
| 教師あり学習後の保存（`train`） | `BinFileRecorder` | Burn バイナリファイル形式 |
| WASM 経由の読み込み（`load_nn_model`） | `BinBytesRecorder` | バイト列から直接ロード |

`BinBytesRecorder` はバイト列から直接モデルを復元するため、ファイルシステムが存在しないブラウザ環境（WASM）でも動作する。

## 互換性

旧モデルからの移行により、モデル構造が変更された（FiLM入力 24次元（ツモ one-hot のみ、残り手数比率は削除）、Policy Head + Value Head の Dual Head 構成、forward() が `(policy_logits, value)` タプルを返す）。既存の学習済みモデル（`artifacts/puyo_model.bin`）は互換性がない。再学習が必要。
