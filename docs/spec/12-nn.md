# ニューラルネットワーク仕様

## 概要

盤面の評価をヒューリスティックではなく CNN（畳み込みニューラルネットワーク）で行うための、モデル定義と入力エンコーディングを提供する。機械学習フレームワークには [Burn](https://burn.dev/) を使用する。

## クレート構成

```
crates/puyo-nn/
├── src/
│   ├── lib.rs          # モジュール公開
│   ├── encoding.rs     # 盤面 → テンソル変換
│   └── model.rs        # CNN モデル定義
└── Cargo.toml
```

## 依存関係

| クレート | 用途 |
|---------|------|
| `burn` | ニューラルネットワークフレームワーク |
| `puyo-core` | `Board`, `PuyoColor`, 定数類, `chain::find_groups` |

## 盤面エンコーディング (`encoding`)

盤面を10チャンネルの浮動小数点テンソルに変換する。チャンネル0〜3は色one-hot形式、チャンネル4〜9は列別連鎖ステップマップ。

### 定数

| 名前 | 値 | 説明 |
|------|-----|------|
| `NUM_CHANNELS` | 10 | color one-hot 4ch + chain step maps 6ch |
| `TENSOR_SIZE` | 840 | `NUM_CHANNELS × ROWS × COLS` = 10 × 14 × 6 |

### テンソルレイアウト

```
[channel][row][col] = [10][14][6]
```

| チャンネル | 内容 | 値域 |
|-----------|------|------|
| 0 | Red (one-hot) | {0, 1} |
| 1 | Green (one-hot) | {0, 1} |
| 2 | Blue (one-hot) | {0, 1} |
| 3 | Yellow (one-hot) | {0, 1} |
| 4 | col 0 のベストトリガーの連鎖ステップマップ | [0, 1] |
| 5 | col 1 のベストトリガーの連鎖ステップマップ | [0, 1] |
| 6 | col 2 のベストトリガーの連鎖ステップマップ | [0, 1] |
| 7 | col 3 のベストトリガーの連鎖ステップマップ | [0, 1] |
| 8 | col 4 のベストトリガーの連鎖ステップマップ | [0, 1] |
| 9 | col 5 のベストトリガーの連鎖ステップマップ | [0, 1] |

#### チャンネル0〜3（色one-hot）

各セル `(col, row)` の色に対応するチャンネルが 1.0、それ以外は 0.0。Empty セルは全チャンネル 0.0（Emptyチャンネルは廃止、4色の排他性から暗黙的に判定可能）。

#### チャンネル4〜9（連鎖ステップマップ）

各列 N（N=0..5）について、その列にトリガーぷよを仮想的に落とした場合の連鎖解決をシミュレーションし、各セルが何ステップ目で消えたかを記録する。

**計算ロジック:**

1. 現盤面の即時連鎖をチェック（トリガーなし）
2. 4色 × 最大3個のトリガーぷよを仮想的に落とす（4パターン）
3. 最長連鎖を発生させたパターンを選択
4. 各セルの値: `step / 19.0`（[0, 1] にクランプ）。消えないセルは 0。19 は理論上の最大連鎖数。

**例:**
```
col 2 に Red×3 を落とすと5連鎖発生
ch6 (col2のステップマップ):
  col: 0    1    2    3    4  5
row3: .    .    .    3/19 .  .
row2: .    2/19 2/19 2/19 .  .
row1: .    1/19 1/19 .    .  .
row0: 1/19 1/19 .    .    .  .
(N/19 ≈ step N を 19 で割った値)
```

**計算コスト:** 6列 × 4色 = 24シミュレーション。CNN推論に比べ無視可能。

### インデックス計算

```
index = channel * ROWS * COLS + row * COLS + col
```

### API

```rust
pub fn board_to_tensor_data(board: &Board) -> [f32; TENSOR_SIZE]
```

内部関数:
- `compute_chain_step_maps(board: &Board) -> [[[f32; ROWS]; COLS]; COLS]` — 6列分の連鎖ステップマップを計算
- `simulate_with_tracking(board: &Board) -> ([[f32; ROWS]; COLS], u32)` — チェイン解決しながら各セルの消えるステップを追跡

### テンソル変換

`board_to_tensor_data` で得られた `[f32; 840]` の1次元配列は、NN に入力する際に4次元テンソルに reshape する。

```
[840] → reshape → [batch, 10, 14, 6]
                   │      │   │   └── COLS
                   │      │   └────── ROWS
                   │      └────────── NUM_CHANNELS
                   └───────────────── バッチサイズ
```

## CNN 価値ネットワーク (`model`)

### アーキテクチャ: `PuyoValueNet`

盤面を入力として、スカラー評価値を出力する回帰モデル。Residual接続（残差接続）を採用し、勾配消失を抑えつつ表現力を確保している。

#### `ResidualBlock`

同一チャンネル数を維持する残差ブロック。入力をショートカット接続で出力に加算する。

```
x → Conv(3×3) → ReLU → Conv(3×3) → (+) → ReLU → y
|                                     ↑
└─────────────────────────────────────┘
```

#### 全体構成

| レイヤー | 種類 | 入力 | 出力 | カーネル | パディング | 備考 |
|---------|------|------|------|---------|-----------|------|
| stem | Conv2d | 10ch | 32ch | 3×3 | Same | 入力チャンネル射影 |
| relu | ReLU | - | - | - | - | |
| res_block ×2 | ResidualBlock | 32ch | 32ch | 3×3 | Same | 残差接続付き |
| head_conv | Conv2d | 32ch | 64ch | 1×1 | - | チャンネル拡張 |
| relu | ReLU | - | - | - | - | |
| pool | AdaptiveAvgPool2d | 64ch | 64ch | → 4×3 | - | |
| flatten | Reshape | 64×4×3 | 768 | - | - | |
| linear1 | Linear | 768 | 128 | - | - | |
| relu | ReLU | - | - | - | - | |
| linear2 | Linear | 128 | 1 | - | - | |

#### 定数

| 名前 | 値 | 説明 |
|------|-----|------|
| `RESIDUAL_CHANNELS` | 32 | Residualブロック内のチャンネル数 |
| `NUM_RESIDUAL_BLOCKS` | 2 | Residualブロックの個数 |
| `HEAD_CHANNELS` | 64 | ヘッド部のチャンネル数 |
| `POOL_H` / `POOL_W` | 4 / 3 | AdaptiveAvgPool2d の出力サイズ |
| `HIDDEN_SIZE` | 128 | 全結合層の隠れ層サイズ |

### 入出力

- **入力形状**: `[batch, 10, 14, 6]`（color one-hot + chain step maps エンコード済み盤面）
- **出力形状**: `[batch, 1]`（スカラー評価値）

### 初期化

```rust
let config = PuyoValueNetConfig::new();
let model = config.init::<B>(&device);
```

## モデルの保存・読み込み

| 用途 | レコーダー | 形式 |
|------|-----------|------|
| 教師あり学習後の保存（`train`） | `CompactRecorder` | Burn 標準バイナリ形式 |
| WASM 経由の読み込み（`load_nn_model`） | `BinBytesRecorder` | バイト列から直接ロード |
| 自己対戦中のターゲットネットワーク更新 | 一時ファイルを介した保存→再ロード | `CompactRecorder` |

`BinBytesRecorder` はバイト列から直接モデルを復元するため、ファイルシステムが存在しないブラウザ環境（WASM）でも動作する。

## 互換性

チャンネル数の変更（6→10）により、既存の訓練データ（`data/training_data.bin`）と学習済みモデル（`artifacts/puyo_model.bin`）は互換性がない。再生成・再学習が必要。
