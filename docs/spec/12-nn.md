# ニューラルネットワーク仕様

## 概要

盤面と3ツモ情報から最善の配置を直接選択する Policy Network（CNN + FiLM Conditioning）のモデル定義と入力エンコーディングを提供する。機械学習フレームワークには [Burn](https://burn.dev/) を使用する。

## クレート構成

```
crates/puyo-nn/
├── src/
│   ├── lib.rs          # モジュール公開
│   ├── encoding.rs     # 盤面 → テンソル変換
│   └── model.rs        # CNN モデル定義
└── Cargo.toml
```

## 依存関係

| クレート | 用途 |
|---------|------|
| `burn` | ニューラルネットワークフレームワーク |
| `puyo-core` | `Board`, `PuyoColor`, 定数類 |

## 盤面エンコーディング (`encoding`)

盤面を6チャンネルの浮動小数点テンソルに変換する。チャンネル0〜3は色one-hot形式、チャンネル4は占有マップ、チャンネル5は連結度マップ。

### 定数

| 名前 | 値 | 説明 |
|------|-----|------|
| `NUM_CHANNELS` | 6 | color one-hot 4ch + occupancy 1ch + adjacency 1ch |
| `TENSOR_SIZE` | 504 | `NUM_CHANNELS × ROWS × COLS` = 6 × 14 × 6 |

### テンソルレイアウト

```
[channel][row][col] = [6][14][6]
```

| チャンネル | 内容 | 値域 |
|-----------|------|------|
| 0 | Red (one-hot) | {0, 1} |
| 1 | Green (one-hot) | {0, 1} |
| 2 | Blue (one-hot) | {0, 1} |
| 3 | Yellow (one-hot) | {0, 1} |
| 4 | 占有マップ (occupancy) | {0, 1} |
| 5 | 連結度マップ (adjacency) | [0, 1] |

#### チャンネル0〜3（色one-hot）

各セル `(col, row)` の色に対応するチャンネルが 1.0、それ以外は 0.0。Empty セルは全チャンネル 0.0（4色の排他性から暗黙的に判定可能）。

#### チャンネル4（占有マップ）

ぷよが存在するセルは 1.0、Empty セルは 0.0。色に依存しない空間構造情報を提供する。

#### チャンネル5（連結度マップ）

各セルの上下左右4方向について同色の隣接ぷよ数をカウントし、4.0 で割って正規化。Empty セルは 0.0。連鎖の種となる同色グループの構造を表現する。

### インデックス計算

```
index = channel * ROWS * COLS + row * COLS + col
```

### API

```rust
pub fn board_to_tensor_data(board: &Board) -> [f32; TENSOR_SIZE]
pub fn pieces_to_tensor_data(current: &Piece, next: &Piece, next_next: &Piece) -> Vec<f32>
```

### 盤面テンソル変換

`board_to_tensor_data` で得られた `[f32; 504]` の1次元配列は、NN に入力する際に4次元テンソルに reshape する。

```
[504] → reshape → [batch, 6, 14, 6]
                   │      │   │   └── COLS
                   │      │   └────── ROWS
                   │      └────────── NUM_CHANNELS
                   └───────────────── バッチサイズ
```

### ツモエンコーディング

`pieces_to_tensor_data()` は3ツモ（current, next, next_next）の色情報を24次元ベクトルに変換する。

```
3ツモ × 2色（axis, satellite） × 4色 one-hot = 24次元
```

各ツモの axis_color と satellite_color をそれぞれ4色の one-hot（Red, Green, Blue, Yellow）に変換し、順に連結する。

## CNN Policy Network (`model`)

### アーキテクチャ: `PuyoPolicyNet`

盤面と3ツモ情報を入力として、24次元の配置 logits を出力する分類モデル。Residual接続（残差接続）と FiLM Conditioning を採用し、ツモ情報に基づいて特徴マップを条件付けする。

#### FiLM Conditioning

Feature-wise Linear Modulation（FiLM）により、ツモ情報を畳み込み特徴マップに注入する。

```
pieces(24) → Linear(24→64) → ReLU → Linear(64→128) → split → gamma[64] + beta[64]
```

FiLM ジェネレータが出力する gamma と beta は、各 `FiLMResidualBlock` で特徴マップをチャンネルごとにアフィン変換する:

```
output = gamma * features + beta
```

#### `FiLMResidualBlock`

FiLM Conditioning 付きの残差ブロック。入力をショートカット接続で出力に加算する。

```
x → Conv(3×3) → ReLU → Conv(3×3) → FiLM(gamma, beta) → (+) → ReLU → y
|                                                          ↑
└──────────────────────────────────────────────────────────┘
```

#### 全体構成

| レイヤー | 種類 | 入力 | 出力 | カーネル | パディング | 備考 |
|---------|------|------|------|---------|-----------|------|
| film_gen | Linear×2 | 24 | 128 | - | - | FiLM ジェネレータ（→ gamma[64] + beta[64]） |
| stem | Conv2d | 6ch | 64ch | 3×3 | Same | 入力チャンネル射影 |
| relu | ReLU | - | - | - | - | |
| res_block ×6 | FiLMResidualBlock | 64ch | 64ch | 3×3 | Same | FiLM 条件付き残差接続 |
| head_conv | Conv2d | 64ch | 128ch | 1×1 | - | チャンネル拡張 |
| relu | ReLU | - | - | - | - | |
| pool | AdaptiveAvgPool2d | 128ch | 128ch | → 4×3 | - | |
| flatten | Reshape | 128×4×3 | 1536 | - | - | |
| linear1 | Linear | 1536 | 256 | - | - | |
| relu | ReLU | - | - | - | - | |
| linear2 | Linear | 256 | 24 | - | - | |

#### 定数

| 名前 | 値 | 説明 |
|------|-----|------|
| `RESIDUAL_CHANNELS` | 64 | Residualブロック内のチャンネル数 |
| `NUM_RESIDUAL_BLOCKS` | 6 | Residualブロックの個数 |
| `HEAD_CHANNELS` | 128 | ヘッド部のチャンネル数 |
| `POOL_H` / `POOL_W` | 4 / 3 | AdaptiveAvgPool2d の出力サイズ |
| `HIDDEN_SIZE` | 256 | 全結合層の隠れ層サイズ |
| `NUM_ACTIONS` | 24 | 出力次元（6列 × 4方向） |
| `PIECE_INPUT_SIZE` | 24 | ツモ入力次元（3ツモ × 2色 × 4 one-hot） |
| `FILM_HIDDEN` | 64 | FiLM ジェネレータ隠れ層サイズ |

### 入出力

- **盤面入力形状**: `[batch, 6, 14, 6]`（color one-hot + occupancy + adjacency エンコード済み盤面）
- **ツモ入力形状**: `[batch, 24]`（3ツモの色 one-hot エンコーディング）
- **出力形状**: `[batch, 24]`（配置 logits）

### 初期化

```rust
let config = PuyoPolicyNetConfig::new();
let model = config.init::<B>(&device);
```

## モデルの保存・読み込み

| 用途 | レコーダー | 形式 |
|------|-----------|------|
| 教師あり学習後の保存（`train`） | `BinFileRecorder` | Burn バイナリファイル形式 |
| WASM 経由の読み込み（`load_nn_model`） | `BinBytesRecorder` | バイト列から直接ロード |

`BinBytesRecorder` はバイト列から直接モデルを復元するため、ファイルシステムが存在しないブラウザ環境（WASM）でも動作する。

## 互換性

Value Network（`PuyoValueNet`）から Policy Network（`PuyoPolicyNet`）への移行により、モデル構造が変更された（出力 `[batch, 1]` → `[batch, 24]`、FiLM Conditioning 追加）。既存の訓練データ（`data/training_data.bin`）と学習済みモデル（`artifacts/puyo_model.bin`）は互換性がない。再生成・再学習が必要。
