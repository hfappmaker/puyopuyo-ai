未コミットのコード変更を繰り返しレビュー・修正し、共通指摘がゼロになるまで自動で改善を続ける。

## 手順

### 1. 差分取得
`git diff` を実行し、未コミットの変更差分を取得する。差分がない場合は「レビュー対象の変更がありません」と報告して終了する。

### 2. 反復レビュー＆修正ループ（最大5回）

以下をイテレーションとして最大5回繰り返す。各イテレーションの開始時に `=== イテレーション N/5 ===` と表示する。

#### 2a. 差分の再取得
`git diff` を実行し、現時点の未コミット差分を取得する。

#### 2b. 並列レビュー（3つのサブエージェント）
以下の3つのサブエージェント（Agent tool）を **1つのメッセージで同時に** 起動する。各エージェントには差分の全文と対象ファイルのパスを渡し、該当ファイルを読んだ上で分析させる。

##### エージェント1: バグ検出
観点: ロジックエラー、境界値ミス、off-by-one、未処理のエッジケース、型の不整合、パニックの可能性
出力形式: 各指摘を `[BUG-1]`, `[BUG-2]`, ... として、ファイルパス・行番号・問題の説明・修正案を含む JSON 配列で返す。

##### エージェント2: 設計改善
観点: 構造の改善、責務の分離、可読性、命名、不要なコード、SOLID原則違反、既存パターンとの一貫性
出力形式: 各指摘を `[DESIGN-1]`, `[DESIGN-2]`, ... として、ファイルパス・行番号・問題の説明・修正案を含む JSON 配列で返す。

##### エージェント3: パフォーマンス最適化
観点: 不要なコピー・clone、アルゴリズムの非効率、メモリ割り当て、キャッシュ効率、不要な計算
出力形式: 各指摘を `[PERF-1]`, `[PERF-2]`, ... として、ファイルパス・行番号・問題の説明・修正案を含む JSON 配列で返す。

#### 2c. 共通指摘の抽出
3つのエージェントの結果を統合し、**2つ以上のエージェントが同一箇所（同じファイル・同じコード領域）について類似の問題を指摘した項目** だけを抽出する。
1つのエージェントだけが指摘した項目は除外する。

#### 2d. 判定
- **共通指摘が0件の場合**: ループを終了し、ステップ3へ進む。
- **共通指摘がある場合**: 以下のテーブルで表示してからステップ2eへ進む。

| # | ファイル | 行 | 観点 | 問題 | 修正案 |
|---|---------|-----|------|------|--------|

#### 2e. 自動修正
共通指摘の修正を **ユーザー承認なしで** 即座に実装する。

#### 2f. テスト実行
`cargo test --workspace` を実行する。
- **テスト失敗**: ループを即座に停止し、失敗内容をユーザーに報告して終了する。
- **テスト成功**: 次のイテレーション（ステップ2a）へ戻る。

### 3. 終了報告

ループ終了時に以下を報告する:

- **指摘ゼロで終了した場合**: 「✅ 全ての共通指摘が解消されました（N回のイテレーションで完了）」
- **最大回数に達した場合**: 「⚠️ 最大イテレーション回数（5回）に達しました。以下の指摘が残っています:」として残りの指摘をテーブルで表示する。

最後に全イテレーションのサマリーを表示する:

| イテレーション | 共通指摘数 | 修正内容 |
|--------------|-----------|---------|

## 注意事項

- 各サブエージェントは **リードオンリー**（コードの読み取りと分析のみ、編集は行わない）
- 指摘は具体的に: ファイルパスと行番号を必ず含める
- 修正案は実装可能な具体的コードで示す
- テスト失敗時はそれ以上の修正を行わず、即座に停止する
- 修正によって新たな問題が導入されていないか、各イテレーションで再検証される
